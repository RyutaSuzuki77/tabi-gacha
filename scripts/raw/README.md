# 元データ

`towns.csv` の元になったデータの記録。

**年次と人口の区分は、検証スクリプトでは検出できない。** ここが唯一の記録になるので、
データを落としたら必ず埋めること。

## データセット

- **データセット名**：住民基本台帳に基づく人口、人口動態及び世帯数調査
- **公表元**：総務省
- **一覧ページ**：https://www.e-stat.go.jp/stat-search/files?toukei=00200241&tstat=000001039591
- **地域区分**：市区町村
- **提供形式**：Excel（CSVは提供されていないため、Excelを「CSV UTF-8」で保存し直した）

### ↓ ここはデータを落とした人が埋める

- **落としたファイル名**：【総計】市区町村別人口、人口動態及び世帯数 26ssjin.xlsx
- **年次**：令和8年1月1日現在
- **人口の区分**：日本人住民と外国人住民の合計
- **取得日**：2026/10/24

### 補足：今回のデータは厳密には著作権の対象外

規約には次の記載がある。

> 数値データ、簡単な表・グラフ等は著作権の対象ではありませんので、これらについては
> 本利用ルールの適用はなく、自由に利用できます。

本アプリが使うのは市区町村名と人口の数値であり、この例外に当たるため、**出典表記は
法的な義務ではない**。それでも表記するのは次の理由による。

- 「実在の市町村の実データを使っている」という主張の裏付けになる
- AIが生成した文章（ミッション・行き方のコツ）と統計データを同じ画面に並べるため、
  どこまでが公的な数字なのかを読み手に示す必要がある

## 加工した内容

### CSVに対して行った加工

- ExcelをCSV UTF-8 に変換し、`code,prefecture,name,population` の4列に整形
- 自治体コードは文字列として扱い、先頭のゼロを保持
- **行の除外はしていない。** 区・郡の集計行・人口10万人以上・人口の少ない行は、
  いずれもCSVに残っている

### 骨格生成時（`npm run data:skeleton`）に行う処理

CSVは書き換えず、読み込み時に次の正規化と除外を行う。

**正規化**（`scripts/buildSkeleton.ts` の `normalizeRow`）

- 自治体コードが6桁の場合は5桁に落とす（6桁目は検査数字。先頭5桁を `id` として使う）

**除外**（`scripts/skeleton.logic.ts` の `buildSkeletonTown`）

- 名称が「市」「町」「村」で終わらない行（`isExcludedName`）。次を含む
  - 「区」で終わる行＝特別区・政令市の行政区（仕様 4.1）
  - 「郡」で終わる行＝e-Stat の郡ごとの集計行（例：「秋田県鹿角郡」「岡山県真庭郡」）。
    自治体ではなく、構成する町村の人口の合計なので、残すと二重に数えることになる。
    郡を含む自治体（「紋別郡西興部村」）は町村で終わるので除外されない
  - 「島しょ」のような広域の集計行
- 人口が数値として読めない行
- 人口100人未満の行＝人口0のまま一覧に残る自治体（`MIN_POPULATION`、仕様 4.1）
- 人口10万人以上の行（レア度が付かないため。仕様 4.1）
- 都道府県名が地方に割り当てられない行

その後、人口からレア度を機械的に付与し（仕様 4.2）、地方×レア度ごとに件数を絞る（仕様 11.3）。

## 座標を取得していない理由

Googleマップの目的地は「都道府県名＋市区町村名」のテキストで指定しているため、
緯度経度を持つ必要がない（仕様 6.1）。

これにより、測地系のズレ（日本測地系のデータをそのまま渡すと数百メートル単位で
ずれる）、代表点の選定（境界データの重心は山林を含む町では人のいない山中に落ちる）、
配布形式の変換（市区町村役場の座標はGMLとシェープファイルのみで提供される）という
3つの問題を回避している。
