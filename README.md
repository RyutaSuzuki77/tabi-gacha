# 旅ガチャ

1日1回ガチャを引くと、日本の小さな町が1つ当たる。その町でやることが3つ付いてくるので、実際に行って達成する。旅の口実をつくるためのアプリ。

有名な観光地は出ない。人口10万人未満の市町村だけを対象にしていて、**人口が少ない町ほどレア度が高い**。

- 本番: https://tabi-gacha.vercel.app
- 設計の意図と判断の記録: [`docs/superpowers/specs/2026-10-24-machi-gacha-design.md`](docs/superpowers/specs/2026-10-24-machi-gacha-design.md)
- 手動確認の手順書: [`docs/manual-check.md`](docs/manual-check.md)

## 機能

### ガチャ

- **1日1回・引き直し不可**。端末のローカル暦日で判定する
- **全国モード**と**地方モード**（北海道／東北／関東／中部／近畿／中国／四国／九州沖縄の8区分）。地方は利用者が自分で選ぶ
- 二段階抽選：レア度を重み付きで引き、そのレア度の町から一様に1つ選ぶ

### レア度

人口から機械的に決まる。恣意的な設定はない。

| レア度 | 人口 | 出現重み | ポイント |
|---|---|---|---|
| SSR | 3,000人未満 | 8 | 100 |
| SR | 3,000〜9,999人 | 22 | 50 |
| R | 10,000〜29,999人 | 35 | 25 |
| N | 30,000〜99,999人 | 35 | 10 |

人口10万人以上の市区町村は**出題対象外**（データ生成の段階で除外される）。

### ミッション

1回の抽選につき3枚付く。

- **固有ミッション 1枚** — その町でしか成立しないもの
- **汎用ミッション 2枚** — どの町でも成立するもの。町のタグで条件が合うものだけが候補になる

達成は**自己申告**。チェックを押せばポイントが入る。GPSによる到達判定もAIによる写真判定も行わない。

### ポイントと称号

獲得ポイント = **レア度のポイント × 達成したミッション数**。累計で称号が上がる。

| 累計 | 称号 |
|---|---|
| 0 | 旅の見習い |
| 100 | 寄り道の人 |
| 500 | 旅人 |
| 1,500 | 辺境の開拓者 |
| 5,000 | 日本を踏み尽くす者 |

### コレクションと写真

- 引いた町はカードとして残る。並べ替えができる
- カードに**その旅で撮った写真**を貼れる。タップで拡大表示（キーボードの左右・スワイプで送れる）
- 写真は端末の IndexedDB に Blob で保存する

### 行き方

- カードに「行き方のコツ」（最寄り駅、駅から先の交通手段、季節の注意など）が載る
- **Googleマップで経路をひらく**ボタン。APIキー不要
- 出発地はアプリ側で指定しない。Googleマップが現在地を使う。変えたい場合はGoogleマップ側で編集する

### デモモード

プロフィール画面の奥にある。発表用。

- 1日1回の制限を外す
- 次に引くレア度を固定する

### 保存とプライバシー

- **サーバーを持たない。** 完全な静的SPAで、実行時にサーバー処理は動かない
- カードとプロフィールは `localStorage`、写真は `IndexedDB`。すべて端末の中だけ
- **位置情報を取得しない**
- 端末を変えると引き継げず、ブラウザのデータを消すと失われる。この代償はアプリ内に明記している

## ガチャに出る町を追加する

> 対象は**日本の市区町村**（国ではない）。データは `public/data/towns.json` にある。

### 最初に知っておくこと

**`enriched: false` の町は抽選に出ない。** 骨格だけ作っても出現しないので、必ず補完までやる。

現在の状態:

```
全360件 / 補完済み 64件（SSR・SR・R・N 各16件）
```

### 方法A：対象を増やす（推奨）

元データ `scripts/raw/towns.csv` には全国の市区町村が入っている。そこから「1地方1レア度あたり何件」を指定して選抜する。

```bash
npm run data:skeleton          # 既定は 10件 → 8地方 × 4レア度 × 10 = 320件
npx tsx scripts/buildSkeleton.ts 20   # 件数を変えたいとき
```

**再実行しても補完済みの内容は失われない。** 既存の `towns.json` から `enriched: true` の町を引き継ぎ、選抜から外れた町も出力に残す。これは利用者の端末に残るカードが町のidを参照しているためで、**idは増えるだけで減らない**。

### 方法B：特定の町を手で足す

`public/data/towns.json` に直接追加する。

```json
{
  "id": "01409",
  "name": "余市郡赤井川村",
  "prefecture": "北海道",
  "region": "北海道",
  "population": 1475,
  "rarity": "SSR",
  "tags": [],
  "uniqueMission": "",
  "accessTips": "",
  "enriched": false
}
```

| フィールド | 規則 |
|---|---|
| `id` | 自治体コード5桁。重複不可 |
| `name` | **必ず「市」「町」「村」で終わる**。区・郡で終わる名前は検証で弾かれる |
| `region` | 上記8区分のいずれか。三重県は近畿に入れる |
| `population` | 100以上 100,000未満 |
| `rarity` | **人口と矛盾すると検証で落ちる**。上の表のとおりに付ける |

### 補完する（ここをやらないと出ない）

`uniqueMission`・`accessTips`・`tags` を埋めて `enriched` を `true` にする。

補完用のプロンプトが [`scripts/prompts/town-enrichment.md`](scripts/prompts/town-enrichment.md) にある。未補完の町のJSONを渡して、返ってきた配列で差し替える。

**守るべき制約**（検証で機械的にチェックされる）:

- `uniqueMission` — 12〜80文字。汎用プールと同じ文面にしない。「地元の人に話しかけ」のような汎用表現を含めない
- `accessTips` — 20〜200文字。**出発地に依存する表現を書かない**（「東京から」「都心から」は禁止）。**所要時間も書かない**（「車で3時間」「約90分」は、どこから来るかで嘘になる）
- `tags` — 次の語彙のみ。0個でもよい。重複不可

  `海沿い` `山間` `温泉あり` `鉄道駅なし` `離島` `城下町` `湖畔`

  季節で変わる性質（積雪など）はタグにしない。それは `accessTips` に書く。

### 検証する

```bash
npm run data:validate
```

`npm test` にも含まれているので、コミット前に必ず通ること。

### 元データを差し替える場合

`scripts/raw/towns.csv` の出典・年次・ライセンス・加工内容は [`scripts/raw/README.md`](scripts/raw/README.md) に記録されている。**年次と人口の区分は検証スクリプトでは検出できない**ので、差し替えたら必ずそこを更新する。

列の形が変わる場合は `scripts/buildSkeleton.ts` の `normalizeRow` を直す。

## ミッションを追加する

### 汎用ミッション（どの町でも出る）

`public/data/generic-missions.json` に追加する。現在30件。

```json
{
  "id": "g-talk",
  "text": "地元の人に話しかけて、おすすめを一つ聞く",
  "requiredTags": []
}
```

| フィールド | 規則 |
|---|---|
| `id` | 一意。慣例として `g-` 始まり |
| `text` | 8〜60文字 |
| `requiredTags` | 上記7語彙のみ。重複不可。**空配列なら無条件に成立する** |

`requiredTags` を指定すると、そのタグを**すべて**持つ町でだけ候補になる。

```json
{
  "id": "g-onsen",
  "text": "日帰りで入れる湯を探して、ひとつ浸かる",
  "requiredTags": ["温泉あり"]
}
```

**条件なしのミッションは3つ以上必要。** 1回に2枚引くため、町のタグで候補が枯れたときの補充に使う。3つを切ると検証でエラーになる。

> タグの打ち間違いは症状が出ない。「海沿」と書いてもどの町にも成立せず、プールが黙って縮むだけで誰も気づかない。だから検証で語彙を照合している。

### 固有ミッション（その町だけ）

`public/data/towns.json` の各町の `uniqueMission` を埋める。1町につき1つ。規則は「補完する」の節を参照。

その町の産業・地形・歴史・特産品に根ざした具体的なものにする。存在が確かでない施設名は書かず、確かめに行く形にする。入場料や予約が要るものは避ける。

## ディレクトリ構成

```
src/
  domain/      抽選・レア度・ミッション・ポイント・称号のロジック（UIに依存しない）
  features/    画面（card / profile / gacha / collection）
  data/        データの読み込みと出典の定義
  storage/     localStorage / IndexedDB のスキーマと入出力
  maps/        Googleマップの経路URL組み立て
  ui/          共通コンポーネント
scripts/
  raw/         元データのCSVと、その出典・ライセンスの記録
  prompts/     町データ補完用のプロンプト
  buildSkeleton.ts / skeleton.logic.ts    CSV → towns.json
  validateTowns.ts                        データ検証
public/data/   towns.json / generic-missions.json（配信される実データ）
e2e/           Playwright
docs/          仕様書と手動確認の手順書
```

## デプロイ

Vercel の GitHub 連携。`main` への push で本番、それ以外のブランチで Preview が自動デプロイされる。

設定はすべて自動検出（Framework: Vite / Build: `npm run build` / Output: `dist`）。環境変数はない。`vercel.json` も置いていない。

## データの出典

町名と人口は**住民基本台帳に基づく人口、人口動態及び世帯数調査**（総務省、令和8年1月1日現在）による。

> 出典：政府統計の総合窓口(e-Stat)（https://www.e-stat.go.jp/）

詳細な加工内容とライセンスの扱いは [`scripts/raw/README.md`](scripts/raw/README.md) を参照。

**固有ミッションと行き方のコツはAIが生成した文章**であり、公的な統計データではない。この区別はアプリ内にも明記している。
